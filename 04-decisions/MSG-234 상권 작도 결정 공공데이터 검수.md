# MSG-234 상권 작도 결정 — 그리지 않고, 그려진 것을 검수한다

> [!tldr]
> "서면 A-14" 격자 이름표(MSG-234)의 블로커였던 **상권 30~50개 범위 작도**를 해결: 사람이 며칠간 그리는 대신, **소상공인시장진흥공단 공공데이터(상권 경계)를 자동 변환해 초안을 만들고 사람은 검수만** 한다(팀 분담 1~2시간).
> 실증 완료(7/28): 주요상권현황 CSV(1,227상권, 위경도 원본) + 회식상권 SHP(EPSG:5181 교차 검증)로 **서울 176 + 부산 55 = 초안 231건 자동 생성**, 라이선스 제한 없음, 26행 캡 초과 0건. → **MSG-234 보류 해제, WIP 브랜치 재개**(V8__zones.sql).
> 한계: 이름이 역 출구 단위로 잘게 쪼개짐(통명화는 사람 몫) · 광안리·해운대 등 해변 관광 상권 공백(검수 때 소수 수동 추가) · 폴리곤→사각형 근사. 카카오 API는 원천 불가(범위 정보 없음 + 저장 즉시 약관 위반).

## 이 노트로 답할 수 있는 질문
- MSG-234가 왜 멈춰 있었고 어떻게 풀렸나?
- zone 초안 데이터는 어디서 와서 어떻게 변환되나?
- 실제로 초안 몇 건이 나왔고 남은 사람 작업은 뭔가?
- 왜 카카오 API로는 상권 범위를 못 만드나?
- 공공데이터 상권 경계의 한계(공백 지역·이름 품질)는?
- 좌표계(CRS) 문제는 어떻게 종결됐나?

## 맥락
[[ADR 격자 표시명 zone]]이 확정한 "서면 A-14" 체계는 코드 완성(테스트 36건, WIP 브랜치 보존) 상태였지만, zones 데이터 0행 — "서면이 어디까지인가"는 좌표 공식이 아니라 사람의 지역 지식이라 **누가 30~50개를 그리나**가 미확정으로 보류됨(7/23 MSG-167 후속에서 보류 확인).

## 결정
**공공데이터 초안 + 사람 검수** (제안 문서 cf-26116098의 ③안 채택, 폴백은 수동 작도):
1. **자동 초안** ✅ — 상권 경계 폴리곤 bbox → GridEncoder 양자화(`floor(lat/0.0009)`, `floor(lng/0.00115)`) → min/max_grid_y/x. 산출물 `zones-draft.json`·`zones-draft.geojson`(검수용, 231건).
2. **사람 검수** — geojson.io에 올려 30~50개 선정 + 이름 다듬기("서면역7번 출구"→"서면") + 경계 조정. 3인 분담 1~2시간.
3. **시딩** — 확정본을 ZoneSeeder에 투입, WIP 브랜치(feature/MSG-234-zone-naming) 재개. 마이그레이션은 V8__zones.sql(V7은 MSG-238 선점).

## 기각된 대안
- **순수 수동 작도** — 며칠 소요, 경계 근거 자의적. 지금 방식의 열화판
- **AI 좌표 생성** — 환각 위험, 공공 실측 데이터에 열위
- **행정동 이름으로 버티기** — 디자인 ver 6의 "서면 A-14" 표기 불가, 보류 연장일 뿐
- **카카오 로컬 API를 초안 소스로** — 범위 정보 없음(점만 반환) + 저장 즉시 약관 위반(데브톡 150397). 검색(점 좌표)은 MSG-251 카카오, 범위 저장은 공공데이터로 역할 분리

## 영향·남은 일
- [[ADR 격자 표시명 zone]]의 "MSG-234 보류" 상태 해제 — FE 행정동 폴백 전제도 zone 시딩 후 표시명으로 승격 예정
- 스크럼 안건: 검수 분담 · 광안리·해운대 수동 보강(한 자릿수) · 검수 후 MSG-234 종결
- 데이터 최신성: 주요상권현황 2024-01 기준 — 연 1회 재수집이면 충분
- **후속 (2026-07-30/31, MSG-259)**: 기계장치는 develop 머지 완료, 데이터 롤아웃은 MSG-259로 이관 — 초안 233건(해변 갭필 2 추가)·후보 29곳(공공 17+수동 12) validate PASS, 검수 규칙 4·검증 3층 확정(PR BE#76). 정본 [[zone 표시명 데이터 파이프라인 해설]] · 공공데이터 근거 [[zone 상권 공공데이터 근거]]
