# ADR — 행사 중심 임시 커뮤니티(행사방) 도입, D-7 개설·LIVE 활성화

> [!warning] 상태는 **제안됨**이다
> 확정 기획이 아니다. 백엔드 API와 DB 스키마는 이 결정 범위 밖이고, 시안 검증 뒤 PRD와 개발 스펙에서 따로 정한다.

> [!tldr]
> 지도 홈에 **상시 지역 커뮤니티는 만들지 않는다.** 대신 포켓몬 메가페스타·BTS 부산 공연처럼 도시 안 여러 장소에서 함께 움직이는 대형 행사에 한해 기간 한정 **행사방**을 연다 (2026-08-13 제안).
> 행사 **7일 전에 열어** 정보와 참여 준비를 돕고, 행사가 시작되면 **LIVE로 전환**해 대기·품절·교통 같은 현장 제보를 지도에 붙인다. 고정 칩 4종(핫구역·지역축제·팝업스토어·경로추천)은 그대로 두고, 행사방은 다섯 번째 고정 카테고리가 아니라 **기간이 정해진 임시 칩**이다.
> 중심은 게시판이 아니라 **행사 지도**다. 제보는 장소를 골라 올리고, 글을 누르면 지도가 이동하고 지도에서 장소를 누르면 그 글만 모인다. 지도와 게시판이 따로 노는 구조는 만들지 않는다.

## 이 노트로 답할 수 있는 질문
- 왜 상시 지역 커뮤니티를 안 만들고 행사 단위로 가나?
- 어떤 행사가 행사방 대상인가? 단일 매장 팝업은?
- D-7과 LIVE 상태에서 각각 무엇이 보이나?
- 기존 상단 칩 4종·미션과는 어떤 관계인가?
- 알림은 누구에게 얼마나 가나?
- 이번 결정에서 정하지 않은 것은 무엇인가?

## 맥락
대형 행사는 한 장소에서 끝나지 않는다. 팝업·포토존·체험·굿즈·드론쇼·팬 모임이 도시 여러 곳에서 동시에 열리고, 사용자는 어디에서 무엇이 열리는지, 어느 순서로 돌지, 지금 줄이 얼마나 긴지, 같이 갈 사람이 있는지를 전부 다른 채널에서 찾는다.

현재 지도 홈의 지역축제·팝업스토어·경로추천 칩은 정보를 **유형별**로 나눈다. 그런데 사용자는 "팝업을 보러 부산에 간다"가 아니라 "포켓몬 행사 때문에 부산에 간다"처럼 **행사 단위**로 생각한다.

## 개설 기준
주최자가 지자체인지 민간인지로 가르지 않는다. 아래를 만족하는 행사만 운영자가 등록한다.

- 도시나 넓은 권역에서 방문 수요가 생긴다
- 여러 장소·프로그램·부대행사 중 하나 이상이 있다
- 대기·품절·교통·일정 변경처럼 시간에 따라 달라지는 정보가 있다
- 이동 순서나 동행 정보를 나눌 이유가 있다

단일 매장 팝업이나 한 장소에서 끝나는 소규모 행사는 기존 팝업스토어·지역축제 칩이 다룬다. 행사방은 모든 행사를 받는 기능이 아니다.

## 결정 4가지
1. **고정 칩 4종 유지.** 행사방은 임시 칩이고 MVP에서는 현재 권역의 임시 칩을 **최대 1개만** 노출한다. 후보가 여럿이면 운영 우선순위로 하나를 고른다. 행사가 없으면 임시 칩도 숨겨 기존 지도 홈과 완전히 같다. 단일 선택 토글 규칙도 그대로다. 표시는 `포켓몬 부산 D-7` → `포켓몬 부산 LIVE` → 종료 시 숨김.
2. **7일 전 개설.** 공식 정보가 다 모일 때까지 미루지 않는다. 최소 정보만 먼저 채우고 미확인 항목은 "확인 중"으로 둔다. 정보 수급은 자동 수집보다 **운영자 수동 등록 우선** — 민간 행사가 공공데이터에 없다는 이유로 행사방이 안 열리는 일을 피하기 위해서다.
3. **행사 중 LIVE 전환.** 왼쪽 패널은 `행사정보 / 실시간 / 동선` 탭. 제보 범주는 대기 시간·품절·교통과 입장·현장 영상·동행·추천 동선.
4. **알림은 구독자에게만.** 행사방에서 직접 켠 사용자에게, 행사 시작·주요 일정 변경·저장한 일정 임박까지만. 현장 글을 전부 푸시하지 않는다.

## 검토한 대안
| 대안 | 판단 | 이유 |
| --- | --- | --- |
| 상시 지역 커뮤니티 | 기각 | 평소 글이 비기 쉽고 "부산"·"대전"이라는 범위만으로는 사용 목적이 약하다 |
| 공식 행사 정보만 제공 | 기각 | 대기·품절·교통·동행처럼 당일 가장 필요한 정보를 못 채운다 |
| 추천 동선을 첫 화면으로 | 기각 | 사용자는 동선보다 "어떤 행사가 열리는가"를 먼저 고른다. 동선은 행사방 안의 기능 |
| 행사 단위 임시 커뮤니티 | 채택 | 짧은 기간에 같은 목적의 사용자가 모여 정보 밀도가 높고, 장소와 글을 직접 연결할 수 있다 |

## 기존 기획과의 관계
지역축제·팝업스토어는 개별 장소를 찾는 기능으로 남고, 행사방은 그 장소들을 하나의 큰 행사 아래 묶는다. 포켓몬 행사방 안에 부산역 포토존·서면 굿즈샵·광안리 프로그램을 함께 연결하는 식이다.

**미션과는 다르게 취급한다.** 미션은 방문과 영상 기록이 완료 조건이지만 행사방은 정보 탐색과 현장 공유가 목적이다. 장소나 기존 미션을 연결할 수는 있어도 **행사방 참여 자체가 격자 점령이나 미션 완료를 만들지는 않는다.**

## 위험과 대응
초기 정보 부족은 "확인 중" 상태를 허용해 넘기고, 거짓 제보·광고는 신고·작성 제한·장소 선택·출처 구분으로 막는다. 알림 과다는 구독자 한정과 종류 제한으로, 상단 칩 과밀은 임시 칩 1개 상한으로 막는다.

## 검증 기준
행사 하나를 운영자가 등록해 D-7과 LIVE 두 상태만 본다. 지표는 임시 칩 열람률, 알림 신청률, D-7 질문·동행·동선 글 수, LIVE 장소별 제보 작성 수와 조회 수, 지도 장소에서 게시물로 이동한 비율, 신고·숨김 처리 비율.

## 이번에 정하지 않은 것
행사 종료 후 게시물 보존 기간과 읽기 전용 전환, 행사 자동 발굴과 수집, 개설 신청·승인 절차, 실시간 채팅, 여러 행사 칩 동시 노출, 백엔드 API와 DB 스키마.
