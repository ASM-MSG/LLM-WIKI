# 이벤트 허브 검증 — 광안리 파일럿 실험설계

> [!tldr]
> 성민 발제 "지도 + 이벤트 커뮤니티(보드·알림)" 아이디어의 리서치 결론: **빈칸 실재** — 행사 플랫폼은 리스트, 지도는 장소 중심, 당근은 거주지 인증이라 "이벤트 보러 온 방문객"을 받아주는 곳이 없다. FillMap은 미션 3종 데이터·알림 파이프라인·핫구역으로 절반을 이미 보유, 없는 것은 UGC 보드와 이벤트 단위 화면.
> 검증 실험: **2026-11-07 부산불꽃축제**를 코드 변경 0으로 이벤트 허브처럼 수동 운영(JSONL 수동 등재 + 팀원 5~10명 현장 파일럿 + 다이어리 스터디). 판정 3-way — 비공식 연계 행사 10건↑ & 공유 욕구 인당 3건↑이면 PRD 착수, 공유 욕구만 약하면 "제보→핀 승격" 축소, 둘 다 비면 보류.
> 설계 중 사전 실측 3건: ① 앵커 부재(TourAPI 원본 918건에 부산 축제 37건 있지만 불꽃축제 없음) ② 반복 일정 뭉개짐(드론쇼가 1/1~12/31 연중 행사로 적재 — 매주 토요일 정보 소실) ③ 대표 좌표 뭉개짐(광안리 행사 4건이 같은 좌표 35.1538, 129.1185).

## 이 노트로 답할 수 있는 질문
- 이벤트 허브(보드+알림) 아이디어의 시장 빈칸 근거는?
- 실험 전에 이미 나온 실측 3건은 무엇이고 수치는?
- 광안리 파일럿의 질문 8개(Q0~Q7)와 레인 구분은?
- 타임라인(10/1 조사 시작 ~ 11/7 D-day)과 대조군은?
- PRD 착수/축소/보류 판정 기준은?
- 왜 PRD 없이 진행 가능한가(면제 근거)?

## 아이디어와 리서치 결론 (2026-08-19)

발제(성민): 네이버 지도는 장소는 알지만 "지금 이 도시에서 벌어지는 일"은 모른다. MSI 2026 대전(6/28~7/12 DCC, 관람 8만 예상, 팬 페스타·미디어 파사드 등 공식 연계 행사 실재)처럼 메가 이벤트가 열리면 연계 팝업·팬 모임·상권 이벤트가 같이 생기는데, 지도 위에서 한눈에 보고 공유할 곳이 없다. 815 부산도 시 주최 경축식은 보도자료로 잡히지만 단체 주최는 SNS·블로그에 흩어져 검색 불가.

시장 지형 조사 결론:
- **네이버 지도·플레이스**: 장소 축. "행사" 개체 없음, 커뮤니티 없음
- **당근 동네생활·모임**: 거주지 축. 당근모임 MAU 1,000만 돌파(2026 상반기, 모임 수 +74%)로 지역 커뮤니티 수요는 검증 — 그러나 동네 인증이라 방문객 진입 불가
- **이벤터스·온오프믹스·페스타**: 주최자 축(모객·티케팅). 리스트, 지도 아님
- **이벤트맵**: 날짜+지도 축으로 가장 근접 — 발견에서 끝, UGC 없음
- **Luma·Partiful·Eventbrite·Meetup·Fever**: 초대·티켓·큐레이션. "메가 이벤트 주변 생태계" 관점 부재

→ **"이벤트 앵커 지도 + 참가자 커뮤니티" 조합은 빈칸, 축별 수요는 전부 타사가 검증**. 비어 있는 이유는 행사 콘텐츠 단명 + 이중 콜드스타트인데, 메가 이벤트는 시간·공간·관심 응집으로 두 약점이 뒤집힌다(이벤트 하나만 채우면 됨, 기간 한정 = 모더레이션도 한정).

FillMap 보유/부재 대조: 보유 — 미션 3종 실적재(축제 222·팝업 227·코스 148), 뷰포트·상세·진행도 API, 알림 파이프라인(카테고리 7종, MISSION_NEARBY 작업 중), 핫구역, GPS 현장 인증, moderation(영상). 부재 — 게시글(UGC 텍스트) 개체, 이벤트 단위 허브 화면, 관심 등록(팔로우). 동선은 videos(grid_id+시각)로 이미 데이터 존재. [[설계검토 미션·이벤트 기능 추가]]의 발표 서사 "공공·민간 데이터 커버 불가 → 사용자 신호로 감지(핫구역)"의 다음 문장에 해당 — 감지에서 멈추지 않고 그 자리에서 말하게 하기.

## 사전 실측 3건 (실험 설계 중 확인, 2026-08-19)

1. **앵커 부재**: `~/fillmap-data/festivals-tourapi/festivals.jsonl` 918건에 부산 지역 축제 37건(어방축제·옥토버페스타 인 광안리·카운트다운 부산 포함) 존재하나 **부산불꽃축제 자체가 없음**. 8월 수집 시점 문제 가능 → 10월 재수집으로 재확인(Q0). 재수집에도 없으면 "메가 이벤트일수록 공공데이터에 늦게/안 잡힌다" 명제가 실측으로 성립.
2. **반복 일정 뭉개짐**: 광안리 M 드론라이트쇼(실제: 매주 토요일 10분×2회)가 **2026-01-01~2026-12-31**로 적재 — 기간형 스키마(startDate/endDate)에 반복 일정 자리가 없어 연중 상시처럼 보임. 이벤트 허브 대상 행사의 상당수가 반복형이라 스키마 확장 요구 후보.
3. **대표 좌표 뭉개짐**: 광안리 행사 4건(드론쇼·어방축제·청년의 날 축제·카운트다운 부산)이 **같은 좌표 35.1538, 129.1185** — "광안리해수욕장" 장소 대표점 수렴. 같은 장소 행사들의 지도 구분 문제가 스키마 이전에 원천 데이터에서 시작.

## 실험 설계 — 광안리 파일럿

**대상**: 2026-11-07(토) 부산불꽃축제, 광안리해수욕장 일원. 사전행사 13~18시(해변 공연·먹거리 부스), 본쇼 20시. 유료석 예매 10/1 오픈. 당일 드론쇼 휴무. `gwangalli` zone 시드 기존재(25행×17열=425칸, 약 2.5×1.7km) — 표시명 "광안리 A-14" 서버 계산.

**원칙**: 코드 변경 0(기존 기능 운영 + 관측). 앵커는 축제 JSONL, 소규모 연계 행사는 팝업 JSONL 수동 행으로 등재.

**질문 8개 · 레인 2개** (Lane A = 운영 리허설, dev·사용자 불요 / Lane B = 현장 파일럿, 팀원+지인 5~10명. 핫구역 임계 3이라 미출시여도 3명이면 신호 발동):

| Q | 질문 | 방법 | 레인 |
|---|---|---|---|
| Q0 | 10월 재수집 시 불꽃축제가 TourAPI에 잡히나 | 수집 재실행 후 grep, 없으면 수동 등재 전환 | A |
| Q1 | 연계·비공식 행사 몇 건, 몇 개 출처에 흩어져 있나 | 전수 조사 로그(행사 수·출처 수·소요 시간) — 조사 고통 자체가 정량 측정 | A |
| Q2 | 기존 EVENT·POPUP 스키마 등재 가능률 | 전 건 등재 시도, 실패 사유 분류(반복·시간 단위·이동형·좌표 중복·범위 초과) = 스키마 확장 요구 초안 | A |
| Q3 | 9×9 박스의 실제 관람 영역 커버율 | 관람 명당 좌표(해변 양끝·민락수변·이기대) 격자 인코딩 후 대조 | A |
| Q4 | 핫구역이 광안리를 잡나, 몇 시에 | 업로드 후 핫구역 조회 스냅숏, 행사 타임라인 대비 지연. D-7 대조군과 비교 | B |
| Q5 | 업로드 시퀀스로 동선 복원되나 | 당일 videos 참가자별 시간순 폴리라인(read-only 쿼리), 100m 해상도 가독성 판정 | B |
| Q6 | "공유하고 싶은데 못 한 순간" 빈도·유형 | 다이어리 스터디(시각·위치·하고 싶던 행동·실제 한 행동 4칸) = 보드 요구 원천 | B |
| Q7 | 인파 밀집 시 GPS·업로드 내구성 | 19~21시 GPS 오차(격자 오매핑)·30초 영상 업로드 성공률/소요 | B |

**타임라인**: ~9월 말 설계 확정·인원 모집·MISSION_NEARBY dev 배포 확인 → **10/1** 예매 오픈 = 정보 공개 피크, Q1 조사 개시 → 10월 중순 Q0 재수집 → **10/24 (D-14)** 조사 마감·등재·뷰포트 확인·Q3 계산 → **10/31 (D-7, 드론쇼 토요일)** 리허설 = **대조군 확보**(평상시 토요일 신호량) → **11/7 D-day** 파일럿(구역 분산 배치, 자유 관람 동선) → D+7 분석·판정.

**판정 3-way** (사전에 잣대 고정, 경계면 다이어리 정성 판독):
- **착수(PRD行)**: 비공식·단체 연계 행사 ≥10건 & 다이어리 공유 욕구 인당 ≥3건 & 등재 실패가 스키마 한계로 수렴
- **축소**: 연계 행사 많은데 공유 욕구 약함 → 보드 없이 "제보→지도 핀 승격"만 검토
- **보류**: 공식 부대행사뿐 & 다이어리 빈약 → 기존 미션·핫구역으로 충분 판정

**운영 주의**: 팝업 시더 멱등 키 (source, source_key) — 수동 행은 팝가 id와 충돌 없는 대역 선정. `refresh-popups.sh`/크롤러 재실행이 JSONL 재작성 시 수동 행 소실 위험 → 별도 파일 관리 후 적재 직전 병합. 수동 행도 리더 전량 거부 검증(좌표 범위·날짜 순서) 통과 필요.

## 리스크·미결
- **기상 순연**: 파일럿 동반 순연, D-7 대조군은 유효. 순연 공지 확산 경로 자체가 Q1 관측 대상
- **파일럿 편향**: 팀원이라 Q6 과대 측정 우려 → "실제 한 행동"(카톡·인스타·안 함) 칸으로 할인 판독
- **인파 안전**: 핫구역·허브는 몰리는 곳으로 더 보내는 기능 — 제품화 시 혼잡 정보가 안전 정보를 겸해야(PRD 비기능 요구 예약), Q7 실측이 기초 자료
- 서비스 출시 여부(11월 시점)는 Lane B 규모만 결정, 실험 성립엔 무관
